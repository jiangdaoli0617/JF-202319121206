# 01 需求说明书

## 1. 项目背景与目标

高校实验室的器材借还长期依赖纸质台账，存在三个痛点：登记靠手写、责任难追溯、盘点靠人工。
本系统用 RFID 卡为每件器材建立唯一身份标识，把「谁、在什么时候、借走/归还了什么器材」
自动记录并上传至上位机，形成可检索、可导出、不可抵赖的电子台账。

**设计目标**

1. 借还操作全程无纸化，单次操作 ≤ 3 秒完成。
2. 每条记录包含操作人、器材、时间戳、结果四要素，可追溯。
3. 器材状态（在库/借出/超期/异常）在本地 OLED 与上位机双向可见。
4. 断网期间记录不丢失，网络恢复后自动补传。

## 2. 角色与权限

系统采用**双卡模型**：一次借还操作需要刷两张卡 —— 先刷**身份卡**确定操作人，再刷**器材卡**确定标的物。

| 卡片类型 | 归属 | 权限 |
|---------|------|------|
| 管理员卡 | 实验室教师/管理员 | 借还操作 + 新增/删除器材 + 手动登记 + 日志翻页 + 库存查询 |
| 学生卡 | 学生 | 仅借还操作 |
| 器材卡 | 贴在每件器材上 | 无权限，仅作为器材身份标识 |

> **设计说明**：原始需求只区分「管理员卡」与「器材卡」，但器材卡是贴在设备上的标识物，
> 不是操作凭证。若不引入身份卡，则任何人都能拿器材卡完成借出，且日志中无法记录「谁借的」，
> 权限校验与责任追溯都失去对象。故补入学生卡，构成双卡模型。

## 3. 器材状态定义

| 状态 | 含义 | 进入条件 | 退出条件 |
|------|------|---------|---------|
| `IN_STOCK` | 在库 | 入库登记完成 / 归还完成 | 借出成功 |
| `LENT` | 已借出 | 借出成功 | 归还成功 |
| `OVERDUE` | 超期 | 借出时长 > 阈值（默认 7 天，可配置） | 归还成功 |
| `UNKNOWN` | 未登记 | 读到不在档案库中的卡号 | 由管理员执行入库登记 |
| `DISABLED` | 已停用 | 管理员删除/停用该器材 | 由管理员重新启用 |

`OVERDUE` 为衍生状态，由系统定时扫描计算，不单独存储。

## 4. 业务流程

### 4.1 借出

```
待机(显示在库数量)
   │
   ├── 刷身份卡 ──► 校验 ──┬─ 非法/未授权 ──► 红灯 + 长鸣 ──► 记录异常日志 ──► 回待机
   │                       │
   │                       └─ 合法 ──► 绿灯 + 短鸣 ──► 显示"姓名/卡号，请刷器材卡"
   │                                        │
   │                                        └── 15 秒内未刷器材卡 ──► 超时 ──► 回待机
   │
   └── 刷器材卡(15 秒窗口内) ──► 查档案 ──┬─ 未登记 ──► 显示"未登记器材" + 报警 ──► 记录异常
                                        ├─ 已借出 ──► 显示"已借出，借用人 XXX" ──► 拒绝
                                        └─ 在库 ──► 状态置 LENT
                                                    记录：器材ID + 借用人卡号 + 时间戳
                                                    显示"借出成功" ──► 入待传队列 ──► 回待机
```

### 4.2 归还

同借出流程，差异仅在最后一步：器材卡状态若为 `LENT` 或 `OVERDUE`，则置回 `IN_STOCK`
并记录归还时间；若为 `IN_STOCK`，提示「该器材未被借出」并记录异常。

### 4.3 入库登记（管理员）

```
刷管理员卡 ──► 进入管理菜单
   │
   ├── 按键选择「新增器材」
   │      └── 刷一张未使用的器材卡 ──► 分配器材编号 ──► 输入名称 ──► 写入档案 ──► 保存
   │
   ├── 按键选择「删除器材」 ──► 刷器材卡 ──► 状态置 DISABLED ──► 保存
   │
   ├── 按键选择「库存查询」 ──► 显示在库/借出/超期统计，可翻页
   │
   ├── 按键选择「日志翻页」 ──► 本地缓存日志逐条翻看（最多保留最近 N 条）
   │
   └── 按键选择「退出」 / 30 秒无操作 ──► 回待机
```

### 4.4 系统状态机

```
        ┌──────────────────── 上电初始化 ────────────────────┐
        │  外设自检 → 读配置 → 联网 → 时间同步 → 档案同步      │
        └───────────────────────┬───────────────────────────┘
                                ▼
    ┌──────────────────────► IDLE ◄───────────────────────┐
    │                         │                           │
    │              刷身份卡(合法)│                           │
    │                         ▼                           │
    │                   AUTH_OK (15s)                     │
    │                         │                           │
    │              刷器材卡    │  超时 / 操作完成           │
    │                         ▼                           │
    │                   EXECUTE ──► 声光反馈 ──► 入队 ──────┘
    │                                                    
    └── 刷管理员卡 ──► ADMIN_MENU ──► 退出/30s超时 ──► IDLE
```

## 5. 功能模块清单

| # | 模块 | 职责 | 依赖 |
|---|------|------|------|
| 1 | RFID 标签识别 | 读卡号、防冲突、返回 UID | RC522 |
| 2 | STM32 主控逻辑 | 卡号校验、权限判断、状态更新、业务调度、状态机 | 全部 |
| 3 | RTC 时钟记录 | 提供带秒级精度的时间戳；与上位机周期对时 | DS3231 |
| 4 | OLED 显示 | 编号、状态、时间、在库数量、系统状态、菜单 | SSD1306 |
| 5 | 按键交互 | 新增/删除/手动登记/库存查询/日志翻页 | GPIO 按键 |
| 6 | 声光提示 | 成功(绿短鸣)、失败(红双鸣)、未知卡(红长鸣)、异常(红快闪) | 蜂鸣器 + LED |
| 7 | 权限分级 | 管理员/学生卡的身份判别与菜单准入 | 档案库 |
| 8 | WiFi 传输与上位机 | AT 联网、日志上报、断线重连、补传；上位机接收/落库/查询 | ESP8266 + Java |

## 6. 上位机功能

| 功能 | 说明 |
|------|------|
| 器材台账 | 器材列表、当前状态、借用人、借出时间；支持筛选与导出 |
| 历史记录查询 | 按时间范围、器材、操作人、操作类型检索 |
| 实时监控 | WebSocket 推送，现场刷卡操作在页面上实时出现 |
| 档案管理 | 新增/停用器材，变更后下发至 STM32 |
| 时间同步 | 向 STM32 下发标准时间 |
| 数据保存 | SQLite 持久化；支持导出 CSV |

## 7. 硬件清单

| 器件 | 型号 | 接口 | 用途 |
|------|------|------|------|
| 主控 | STM32F103C8T6 | — | 72MHz / 64KB Flash / 20KB RAM |
| 读卡 | RC522 | SPI1 | 13.56MHz，Mifare S50 卡 |
| 时钟 | DS3231 | I2C1 | 带温度补偿，断电走时 |
| 存储 | AT24C02 | I2C1 | 2KB，仅存系统配置 |
| 显示 | SSD1306 OLED 0.96" | I2C1 | 128×64 |
| 联网 | ESP8266-01S | USART2 | AT 固件，TCP Client |
| 交互 | 独立按键 ×4 | GPIO | 菜单与翻页 |
| 提示 | 有源蜂鸣器 + LED×2 | GPIO | 声光反馈 |

> **容量说明**：AT24C02 仅 2KB，不足以承载器材台账与历史日志。本设计中它只保存系统配置
> （设备 ID、WiFi 参数、管理员卡号表、超期阈值）与关键状态位，约占用数百字节。
> 器材档案由上位机持久化，STM32 侧在 RAM 中维护当前档案副本；日志走「上传 + ACK 确认」
> 机制，未确认的记录驻留 RAM 队列，联网后补传。详见 `02-系统架构与通信协议.md` 第 4 节。

## 8. 非功能需求

| 指标 | 要求 |
|------|------|
| 单次识别响应 | ≤ 500 ms |
| 单次借还总耗时 | ≤ 3 s |
| 读卡距离 | 1～3 cm（受金属环境影响） |
| 日志不丢失 | 断网 ≤ 24 h 内的记录全部补传成功 |
| 时间精度 | 与上位机偏差 ≤ 1 s / 天 |
| 掉电保护 | 配置区写入采用「双备份 + 校验和」，任一份损坏可自动回滚 |
| 连续运行 | ≥ 72 h 无死机、无内存泄漏 |

## 9. 验收标准

1. 合法学生卡 + 在库器材卡 → 借出成功，上位机 3 秒内出现对应记录。
2. 未授权卡刷卡 → 红灯长鸣，OLED 提示，上位机记录一条「未授权」异常。
3. 同一器材被借出后再次刷该器材卡 → 提示已借出并拒绝，状态不变。
4. 管理员卡可完成新增/删除器材，上位机台账同步更新。
5. 拔掉网线（断开 ESP8266 连接）后完成 5 次借还，恢复网络后 5 条记录全部补传。
6. 断电重启后，配置与器材状态不丢失，时间继续正确走时。

## 附录 A：相对原始需求的修订说明

| 序号 | 原始要求 | 修订后 | 原因 |
|------|---------|--------|------|
| A1 | 权限仅区分管理员卡与器材卡 | 引入学生身份卡，构成双卡模型 | 器材卡是标识物而非凭证，缺操作人导致权限校验与责任追溯无对象 |
| A2 | AT24C02 存器材台账与日志 | 仅存配置与状态，日志走上报 | 2KB 容量不足；且频繁写 EEPROM 有寿命与掉电风险 |
| A3 | 上位机为 Java 桌面程序 | Java 后端（TCP + WebSocket）+ HBuilderX 前端 | 用户选定 HBuilderX 做前端；浏览器无法开原生 TCP，需 Java 层桥接 |
| A4 | 模块 3「RTC 时钟记录」 | 保留，定位为底层时间服务 | DS3231 与 STM32 内部 RTC 功能重叠，明确只用 DS3231，避免双份 RTC 驱动 |
| A5 | 未定义器材状态集合 | 定义 5 种状态与迁移条件 | 状态机是业务逻辑的基础，缺失会导致 4.1/4.2 无法实现 |
