# 01 需求说明书

## 1. 项目背景与目标

高校实验室的器材借还长期依赖纸质台账，存在三个痛点：登记靠手写、责任难追溯、盘点靠人工。
本系统用 RFID 卡为每件器材建立唯一身份标识，把「谁、在什么时候、借走/归还了什么器材」
自动记录并上传至上位机，形成可检索、可导出、不可抵赖的电子台账。

**设计目标**

1. 借还操作全程无纸化，单次操作 ≤ 3 秒完成。
2. 每条记录包含操作人、器材、时间戳、结果四要素，可追溯。
3. 器材状态（在库/借出/超期/异常）在本地 OLED 与上位机双向可见。
4. 断网期间记录不丢失；断电重启后从 EEPROM 恢复器材状态与待传日志，网络恢复后自动补传。

## 2. 角色与权限

系统采用**双卡模型**：一次借还操作需要刷两张卡 —— 先刷**身份卡**确定操作人，再刷**器材卡**确定标的物。

| 卡片类型 | 归属 | 权限 |
|---------|------|------|
| 管理员卡 | 实验室教师/管理员 | 借还操作 + 新增/删除器材 + 手动登记 + 日志翻页 + 库存查询 |
| 学生卡 | 学生 | 仅借还操作 |
| 器材卡 | 贴在每件器材上 | 无权限，仅作为器材身份标识 |

> **设计说明**：原始需求只区分「管理员卡」与「器材卡」，但器材卡是贴在设备上的标识物，
> 不是操作凭证。若不引入身份卡，则任何人都能拿器材卡完成借出，且日志中无法记录「谁借的」，
> 权限校验与责任追溯都失去对象。故补入学生卡，构成双卡模型。

### 2.1 多终端部署

一个实验室可部署多台终端（如每个器材柜一台），终端之间采用**分区管理**：

- 每台终端由 `DEVICE_ID` 唯一标识（如 `LAB-01-A`、`LAB-01-B`）。
- 器材档案在上位机统一维护，每条记录带归属的 `DEVICE_ID`；同一件器材只归属一台终端。
- STM32 启动时按自身 `DEVICE_ID` 拉取档案，只加载属于自己的那组器材。
- 借还判定完全在本地完成，不依赖网络，因此断网时各终端仍可独立工作。
- 由于器材不重叠，跨终端的并发借还冲突从根本上不存在，无需服务端仲裁。
- 管理员卡、学生卡在全实验室范围内有效，由上位机统一下发到各终端。
- 身份卡名单、器材档案、未上传日志均保存在终端 EEPROM 中，**断网或断电重启后仍可独立工作**。
- 受 AT24C02 2KB 容量限制，单台终端上限为：**40 张身份卡、22 件器材、36 条离线日志**。
  容量分配、双备份与掉电恢复见 `07-EEPROM存储设计.md`。

## 3. 器材状态定义

| 状态 | 含义 | 进入条件 | 退出条件 |
|------|------|---------|---------|
| `IN_STOCK` | 在库 | 入库登记完成 / 归还完成 | 借出成功 |
| `LENT` | 已借出 | 借出成功 | 归还成功 |
| `OVERDUE` | 超期 | 借出时长 > 阈值（默认 7 天，可配置） | 归还成功 |
| `UNKNOWN` | 未登记 | 读到不在档案库中的卡号 | 由管理员执行入库登记 |
| `DISABLED` | 已停用 | 管理员删除/停用该器材 | 由管理员重新启用 |

`OVERDUE` 为衍生状态，由系统每 60 秒定时扫描计算，不单独存储；同一器材每次超期
只上报一次，归还后清除标记。扫描与提醒逻辑见 4.5 节。

## 4. 业务流程

### 4.1 借出

```
待机(显示在库数量)
   │
   ├── 刷身份卡 ──► 校验 ──┬─ 非法/未授权 ──► 红灯 + 长鸣 ──► 记录异常日志 ──► 回待机
   │                       │
   │                       └─ 合法 ──► 绿灯 + 短鸣 ──► 显示"姓名/卡号，请刷器材卡"
   │                                        │
   │                                        └── 15 秒内未刷器材卡 ──► 超时 ──► 回待机
   │
   └── 刷器材卡(15 秒窗口内) ──► 查档案 ──┬─ 未登记 ──► 显示"未登记器材" + 报警 ──► 记录异常
                                        ├─ 已借出 ──► 显示"已借出，借用人 XXX" ──► 拒绝
                                        └─ 在库 ──► 状态置 LENT
                                                    记录：器材ID + 借用人卡号 + 时间戳
                                                    日志入队并落盘(≤225ms) ──► 显示"借出成功" ──► 回待机
```

### 4.2 归还

同借出流程，差异仅在最后一步：器材卡状态若为 `LENT` 或 `OVERDUE`，则置回 `IN_STOCK`
并记录归还时间；若为 `IN_STOCK`，提示「该器材未被借出」并记录异常。

### 4.3 入库登记（管理员）

```
刷管理员卡 ──► 进入管理菜单
   │
   ├── 按键选择「新增器材」
   │      └── 刷一张未使用的器材卡 ──► 分配器材编号 ──► 输入名称 ──► 写入档案 ──► 保存
   │
   ├── 按键选择「删除器材」 ──► 刷器材卡 ──► 状态置 DISABLED ──► 保存
   │
   ├── 按键选择「库存查询」 ──► 显示在库/借出/超期统计，可翻页
   │
   ├── 按键选择「日志翻页」 ──► 本地缓存日志逐条翻看（最多保留最近 N 条）
   │
   └── 按键选择「退出」 / 30 秒无操作 ──► 回待机
```

### 4.4 系统状态机

```
        ┌──────────────────── 上电初始化 ────────────────────┐
        │  外设自检 → 读配置 → 联网 → 时间同步 → 档案同步      │
        └───────────────────────┬───────────────────────────┘
                                ▼
    ┌──────────────────────► IDLE ◄───────────────────────┐
    │                         │                           │
    │              刷身份卡(合法)│                           │
    │                         ▼                           │
    │                   AUTH_OK (15s)                     │
    │                         │                           │
    │              刷器材卡    │  超时 / 操作完成           │
    │                         ▼                           │
    │                   EXECUTE ──► 声光反馈 ──► 入队 ──────┘
    │                                                    
    └── 刷管理员卡 ──► ADMIN_MENU ──► 退出/30s超时 ──► IDLE
```

### 4.5 超期扫描与提醒

STM32 每 60 秒执行一次超期扫描，该逻辑与网络状态无关，断网时照常运行：

```
遍历本地档案
   └─ 状态为 LENT 且 now > due_time
        ├─ 首次发现 → 标记 OVERDUE、超期计数 +1、上报一次超期事件
        └─ 已标记   → 不重复上报
   状态为 IN_STOCK 的器材 → 无需处理（从不超期）
```

**提醒形式**

| 载体 | 行为 |
|------|------|
| OLED | 状态栏常驻显示「超期 N 件」，主界面每 3 秒与在库数量交替显示 |
| 蜂鸣器 | 每 30 分钟轻鸣一声，不打断当前操作 |
| 管理员菜单 | 可翻页查看超期清单：器材编号 + 借用人 + 超期天数 |
| 上位机 | 收到超期事件后在前端高亮该器材 |

归还成功后，该器材的超期标记清除，OLED 上的超期计数相应减少。

## 5. 功能模块清单

| # | 模块 | 职责 | 依赖 |
|---|------|------|------|
| 1 | RFID 标签识别 | 读卡号、防冲突、返回 UID | RC522 |
| 2 | STM32 主控逻辑 | 卡号校验、权限判断、状态更新、业务调度、状态机 | 全部 |
| 3 | RTC 时钟记录 | 提供带秒级精度的时间戳；与上位机周期对时 | DS3231 |
| 4 | OLED 显示 | 编号、状态、时间、在库数量、系统状态、菜单 | SSD1306 |
| 5 | 按键交互 | 新增/删除/手动登记/库存查询/日志翻页 | GPIO 按键 |
| 6 | 声光提示 | 成功(绿短鸣)、失败(红双鸣)、未知卡(红长鸣)、异常(红快闪) | 蜂鸣器 + LED |
| 7 | 权限分级 | 管理员/学生卡的身份判别与菜单准入 | 档案库 |
| 8 | WiFi 传输与上位机 | AT 联网、日志上报、断线重连、补传；上位机接收/落库/查询 | ESP8266 + Java |

## 6. 上位机功能

| 功能 | 说明 |
|------|------|
| 器材台账 | 器材列表、当前状态、借用人、借出时间；支持筛选与导出 |
| 历史记录查询 | 按时间范围、器材、操作人、操作类型检索 |
| 实时监控 | WebSocket 推送，现场刷卡操作在页面上实时出现 |
| 档案管理 | 新增/停用器材，变更后下发至 STM32 |
| 时间同步 | 向 STM32 下发标准时间 |
| 数据保存 | SQLite 持久化；支持导出 CSV |

## 7. 硬件清单

| 器件 | 型号 | 接口 | 用途 |
|------|------|------|------|
| 主控 | STM32F103C8T6 | — | 72MHz / 64KB Flash / 20KB RAM |
| 读卡 | RC522 | SPI1 | 13.56MHz，Mifare S50 卡 |
| 时钟 | DS3231 | 软件 I2C | 带温度补偿，断电走时 |
| 存储 | AT24C02 | 软件 I2C | 256B，存物品表/历史记录 |
| 显示 | SSD1306 OLED 0.96" | 软件 I2C | 128×64 |
| 联网 | ESP8266-01S | USART1 | AT 固件，TCP Client |
| 交互 | 独立按键 ×5 | GPIO | 登记/借出/归还/翻页 |
| 提示 | 有源蜂鸣器 + LED×2 | GPIO | 声光反馈 |

> **容量说明**：AT24C02 共 2KB，需同时承载系统配置、身份卡表、器材档案与离线日志，
> 因此必须精算分配：**40 张身份卡 + 22 件器材 + 36 条离线日志**，恰好用满。
> 各区块地址、双备份机制、写入时序与掉电恢复流程见 `07-EEPROM存储设计.md`。
> 在线运行时日志仍以「上报 + ACK」为主，EEPROM 只保留尚未被确认的部分。

## 8. 非功能需求

| 指标 | 要求 |
|------|------|
| 单次识别响应 | ≤ 500 ms |
| 单次借还总耗时 | ≤ 3 s |
| 读卡距离 | 1～3 cm（受金属环境影响） |
| 日志不丢失 | 断网且断电，未上传记录（≤ 36 条）不丢失，重启后自动续传 |
| 时间精度 | 与上位机偏差 ≤ 1 s / 天 |
| 超期扫描周期 | 60 s |
| 超期提醒间隔 | 30 min |
| 终端数量 | 单实验室支持 ≥ 4 台终端，分区互不干扰 |
| 掉电保护 | 配置、卡表、档案均采用「双备份 + 序号 + CRC」，任一份损坏自动回滚 |
| 离线缓存 | 36 条日志；满时拒绝新操作并提示，不覆盖旧记录 |
| 连续运行 | ≥ 72 h 无死机、无内存泄漏 |

## 9. 验收标准

1. 合法学生卡 + 在库器材卡 → 借出成功，上位机 3 秒内出现对应记录。
2. 未授权卡刷卡 → 红灯长鸣，OLED 提示，上位机记录一条「未授权」异常。
3. 同一器材被借出后再次刷该器材卡 → 提示已借出并拒绝，状态不变。
4. 管理员卡可完成新增/删除器材，上位机台账同步更新。
5. 拔掉网线（断开 ESP8266 连接）后完成 5 次借还，恢复网络后 5 条记录全部补传。
6. 断网完成 5 次借还后**直接断电**，重新上电（仍不联网）：器材状态正确、可继续借还；
   恢复网络后 5 条记录全部补传且无重复。
7. 断电重启后，配置与器材状态不丢失，时间继续正确走时。
8. 人为破坏 EEPROM 某一块的主份，系统能自动使用备份份，数据不丢。

## 附录 A：相对原始需求的修订说明

| 序号 | 原始要求 | 修订后 | 原因 |
|------|---------|--------|------|
| A1 | 权限仅区分管理员卡与器材卡 | 引入学生身份卡，构成双卡模型 | 器材卡是标识物而非凭证，缺操作人导致权限校验与责任追溯无对象 |
| A2 | AT24C02 承载器材台账与全部日志 | 承载配置、卡表、档案与有限离线日志（40/22/36），在线日志以上报为主 | 2KB 容量有限，必须精算分配；离线日志只保留未确认部分 |
| A3 | 上位机为 Java 桌面程序 | Java 后端（TCP + WebSocket）+ HBuilderX 前端 | 用户选定 HBuilderX 做前端；浏览器无法开原生 TCP，需 Java 层桥接 |
| A4 | 模块 3「RTC 时钟记录」 | 保留，定位为底层时间服务 | DS3231 与 STM32 内部 RTC 功能重叠，明确只用 DS3231，避免双份 RTC 驱动 |
| A5 | 未定义器材状态集合 | 定义 5 种状态与迁移条件 | 状态机是业务逻辑的基础，缺失会导致 4.1/4.2 无法实现 |
| A6 | 未说明终端数量与器材归属 | 一个实验室多台终端，按 `DEVICE_ID` 分区管理 | 明确归属后，跨终端并发冲突不存在，无需服务端仲裁 |
| A7 | 未定义超期后的处理方式 | 每 60 s 扫描，OLED 常驻显示 + 30 min 轻提醒 | 超期若不主动提示，管理功能形同虚设 |
| A8 | 未说明身份卡名单如何到达终端 | 由上位机下发，终端存 EEPROM，最多 40 张 | 双卡模型要求离线可校验，名单必须本地化 |
| A9 | 未说明断网重启后的状态恢复 | 配置/卡表/档案/日志全部落 AT24C02，上电先恢复再联网 | 否则断网重启后终端失去档案与未传日志，离线能力不成立 |
