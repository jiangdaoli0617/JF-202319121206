# 04 软件模块与接口设计

本文档定义三端的目录结构与模块对外接口。**接口一旦确定，模块内部实现可自由替换**，
这是「改一处不影响另一处」的落地方式。

## 1. 总体分层原则

| 层 | 目录 | 允许依赖 | 禁止 |
|----|------|---------|------|
| 硬件驱动层 | `bsp/` | STM32 标准外设库 | 依赖任何上层 |
| 抽象中间层 | `middle/` | `bsp/` | 被 `bsp/` 依赖 |
| 应用业务层 | `app/` | `middle/`、`protocol/` | **不得 include 任何 `bsp_*.h`** |
| 协议层 | `protocol/` | 无（纯算法） | 依赖任何层 |

**关键约束**：业务层只认识 `drv_rfid`、`drv_net` 这类抽象接口，不认识 `bsp_rc522`。
因此把 RC522 换成 PN532、把 ESP8266 换成 ESP32，只需重写对应的 `bsp_*` 与 `drv_*`，
`app/` 下的代码一行都不用改。

### 2.2 中间层接口定义

以下接口是**业务层与硬件之间唯一的契约**。

**drv_rfid.h — 读卡**
```c
typedef struct {
    uint32_t uid;          /* 4 字节 UID 压缩为 uint32，取低 32 位 */
    uint8_t  uid_len;      /* 实际长度，Mifare S50 为 4 */
    uint8_t  valid;        /* 1=读到有效卡 */
} rfid_card_t;

void     drv_rfid_init(void);
/* 非阻塞轮询，无卡时返回 0。内部含 2 s 同卡去重（见协议文档 6.4） */
uint8_t  drv_rfid_poll(rfid_card_t *card);
void     drv_rfid_antenna(uint8_t on);   /* 低功耗时可关天线 */
```

**drv_rtc.h — 时间**
```c
typedef struct {
    uint16_t year; uint8_t month, day, hour, minute, second;
    uint32_t unix;         /* 同步维护的 Unix 秒，便于打包上报 */
} rtc_time_t;

void     drv_rtc_init(void);
void     drv_rtc_get(rtc_time_t *t);
void     drv_rtc_set(const rtc_time_t *t);
uint8_t  drv_rtc_is_valid(void);   /* 判断掉电后时间是否仍可信 */
```

**drv_storage.h — 配置存储**

注意此处只提供**配置区**接口，不提供日志存储。日志在 RAM 队列中管理，
由 `app_log` 负责，掉电保护依赖上报确认而非本地持久化。

```c
typedef struct {
    char     device_id[16];
    char     wifi_ssid[32];
    char     wifi_pass[32];
    uint32_t admin_cards[8];      /* 管理员卡号表 */
    uint8_t  admin_count;
    uint16_t overdue_days;
    uint16_t magic;               /* 固定值，用于判断是否已初始化 */
} sys_config_t;

void     drv_storage_init(void);
/* 双备份 + 校验和：任一份损坏自动回滚到另一份 */
uint8_t  drv_storage_load_config(sys_config_t *cfg);
uint8_t  drv_storage_save_config(const sys_config_t *cfg);
```

**drv_display.h — 显示**

按行操作的字符接口，业务层不关心显存布局，换屏只需重写 `bsp_oled`。

```c
void drv_display_init(void);
void drv_display_clear(void);
void drv_display_line(uint8_t line, const char *text);  /* line: 0~7 */
void drv_display_refresh(void);
```

**drv_input.h — 按键**
```c
typedef enum { KEY_NONE, KEY_K1, KEY_K2, KEY_K3, KEY_K4 } key_id_t;

void     drv_input_init(void);
key_id_t drv_input_scan(void);       /* 已含 20 ms 消抖与松手检测，无按键返回 KEY_NONE */
```

**drv_indicator.h — 声光提示**

业务层只说「要什么效果」，不说「哪个灯亮多久」。

```c
typedef enum {
    IND_LEND_OK,        /* 借还成功：绿闪一次 + 短鸣 */
    IND_REJECT,         /* 已借出等业务拒绝：红闪两次 + 双短鸣 */
    IND_UNKNOWN_CARD,   /* 未授权/未登记卡：红长亮 + 长鸣 */
    IND_ERROR,          /* 内部异常：红快闪 + 急促鸣 */
    IND_NET_DOWN,       /* 断网：LED 慢闪，无声音 */
    IND_IDLE            /* 清除所有指示 */
} ind_event_t;

void drv_indicator_init(void);
void drv_indicator_show(ind_event_t ev);   /* 内部非阻塞，由主循环驱动 */
```

**drv_net.h — 网络**

这是**跨端接口的边界**。业务层只提交「一帧数据」并查询链路状态，
不感知 AT 指令、不感知 TCP 重连细节。

```c
typedef enum {
    NET_STATE_IDLE, NET_STATE_CONNECTING, NET_STATE_ONLINE, NET_STATE_ERROR
} net_state_t;

typedef void (*net_rx_cb_t)(const uint8_t *frame, uint16_t len);

void         drv_net_init(const char *ssid, const char *pass,
                          const char *host, uint16_t port);
void         drv_net_register_rx(net_rx_cb_t cb);
void         drv_net_poll(void);           /* 主循环调用，内部驱动重连状态机 */
uint8_t      drv_net_send(const uint8_t *frame, uint16_t len);
net_state_t  drv_net_state(void);
```

### 2.3 应用层接口

**app_fsm.h — 状态机**
```c
typedef enum {
    ST_INIT, ST_IDLE, ST_AUTH_OK, ST_EXECUTE, ST_ADMIN_MENU
} app_state_t;

void        app_fsm_init(void);
void        app_fsm_run(void);      /* 主循环中反复调用，内部完成一轮调度 */
app_state_t app_fsm_state(void);
```

**app_inventory.h — 器材台账**
```c
typedef struct {
    uint16_t equip_id;
    uint8_t  status;
    uint32_t holder_card;      /* 当前借用人卡号，在库时为 0 */
    uint32_t lend_time;        /* Unix 秒 */
    uint32_t due_time;
    char     name[16];
} equip_record_t;

void    app_inventory_init(void);
/* 上位机下发档案时调用；返回写入条数 */
uint16_t app_inventory_bulk_load(const equip_record_t *list, uint16_t count);
uint8_t app_inventory_find(uint16_t equip_id, equip_record_t *out);
uint8_t app_inventory_lend(uint16_t equip_id, uint32_t user_card, uint32_t now);
uint8_t app_inventory_return(uint16_t equip_id, uint32_t user_card, uint32_t now);
uint16_t app_inventory_count_in_stock(void);
uint16_t app_inventory_count_overdue(uint32_t now);
```

**app_log.h — 日志队列**

对外只有「入队」与「主循环驱动」两个动作，重传、ACK、序号管理全部内部完成。

```c
typedef struct {
    uint32_t seq;              /* 全局唯一，掉电重启后延续 */
    uint8_t  op_type;
    uint8_t  result;
    uint16_t equip_id;
    uint32_t user_card;
    uint32_t timestamp;
    uint32_t due_time;
} log_entry_t;

void    app_log_init(void);
uint8_t app_log_push(const log_entry_t *e);   /* 队列满返回 0，此时需等待或丢弃最旧 */
void    app_log_poll(void);                    /* 主循环调用，驱动发送/重传/补传 */
uint16_t app_log_pending(void);                /* 待上传条数，用于 OLED 显示 */
```

### 2.4 主循环结构

```c
int main(void) {
    /* 各层按依赖顺序初始化 */
    bsp_gpio_init();  bsp_spi_init();  bsp_i2c_init();  bsp_usart_init();

    drv_rfid_init();       drv_rtc_init();      drv_storage_init();
    drv_display_init();    drv_input_init();    drv_indicator_init();

    app_config_load();
    app_inventory_init();
    app_log_init();

    drv_net_init(cfg.wifi_ssid, cfg.wifi_pass, cfg.server_host, cfg.server_port);
    drv_net_register_rx(proto_on_frame_received);   /* 协议层回调入口 */

    app_fsm_init();

    for (;;) {
        drv_net_poll();     /* 网络状态机 + 收帧 */
        app_log_poll();     /* 日志发送/重传 */
        app_fsm_run();      /* 读卡、按键、界面、状态迁移 */
        drv_indicator_poll();
    }
}
```

**设计要点**：主循环内所有 `*_poll()` 都必须是非阻塞的，任何一处出现 `delay_ms(500)`
之类的阻塞等待，都会导致其他模块丢事件。需要延时的逻辑一律用「时间戳 + 状态变量」
实现，这是回应难点 2（多总线并发导致卡顿）的核心手段。

### 3.2 关键接口

**TcpSession** —— 一个 STM32 连接对应一个实例
```java
public class TcpSession {
    void onBytes(byte[] data);          // 字节流 → 帧 → 分发
    void send(Frame frame);
    void sendAck(int seq, int result);
}
```

**FrameCodec** —— 与 STM32 侧 `proto_frame.c` 严格对称
```java
public final class FrameCodec {
    public static Frame decode(byte[] raw) throws ProtocolException;
    public static byte[] encode(Frame frame);
}
```

**LogService** —— 幂等入库，重复 seq 直接跳过
```java
public class LogService {
    /** @return true 表示新记录，false 表示重复 seq 被忽略 */
    boolean saveIfAbsent(LogRecord r);
    List<LogRecord> query(LogQuery q);
}
```

**WsServer** —— 前端订阅的唯一出口
```java
public class WsServer {
    void broadcast(String type, Object data);   // 内部序列化为 JSON 文本帧
}
```

### 3.3 分层约束

`net` 只做收发与拆帧，不写业务；`service` 不感知字节与 Socket；`dao` 不感知协议。
替换数据库只需重写 `dao` 包，`service` 以上不动。这与 STM32 端的分层意图一致。

### 4.2 ws.js —— 前端唯一的网络出口

```javascript
// 所有页面都通过这里收发消息，不直接 new WebSocket
export default {
  connect() {},                  // 建立连接，内置指数退避重连
  on(type, handler) {},          // 按消息类型注册处理器
  send(type, data) {}            // 向前端后端发指令（如请求刷新）
}
```

**扩展方式**：后端新增一种推送类型时，页面里加一句
`ws.on('新类型', handler)` 即可，**不影响任何既有处理器**。
这与协议层「新增 Tag 不影响旧解析」是同一个设计思路，贯穿三端。

## 5. 接口变更流程

任何一处接口要改，按以下顺序执行，避免出现「一端改了另一端不知道」：

1. 先改 `docs/02-系统架构与通信协议.md`（若涉及跨端）或本文档（若仅端内）。
2. 按文档改实现，跨端变更在同一个 commit 内完成两端改动。
3. commit message 标注 `proto:` 或 `iface:` 前缀，便于检索。
4. 若为不兼容变更，升协议版本号并打 tag。
