# 08 环境搭建与两台电脑协作手册

> 目的：说清楚「哪些阶段必须用接板子的那台电脑」「每台电脑要装什么」「换机器时怎么做」，
> 避免两台电脑各自闷头开发造成方案分叉。

## 1. 先分清两类工作

毕业设计的工作分两类，**只有第二类受机器限制**。

### A. 不依赖硬件的（两台电脑都能做，随时切换）

- 开题报告、论文、设计文档
- 读代码、改代码、写新模块代码
- Java 上位机开发与测试
- uni-app 前端开发
- 生成图表、截图、答辩 PPT

### B. 依赖硬件的（只能在接着板子的那台做）

- 固件**编译**（需要 Keil + Libraries + 器件包）
- 固件**烧录**（需要 ST-Link 驱动 + 板子插上）
- **上机调试**：编译 → 烧录 → 看现象 → 改代码的快速循环
- **系统联调**：固件 + Java 服务端 + WiFi，需要板子和电脑在同一网段

> 结论：**代码和文档随便在哪台写；要烧板子，就把板子插到那台机器上。**
> 不是"某台机器不能干某事"，而是"那台机器当时得有相应条件"。

## 2. 两台电脑要装的东西

| 项目 | 用途 | 必需时点 |
|---|---|---|
| Git | 同步代码 | 始终 |
| Keil MDK 5 | 编译固件 | 要编译固件时 |
| STM32F1 器件包（DFP） | Keil 认芯片型号 | 要编译固件时 |
| `firmware/Libraries/`（CMSIS + SPL） | 编译依赖 | 要编译固件时 |
| ST-Link 驱动 | 烧录下载 | 要烧板子时 |
| 串口驱动（CH340 等） | 看 printf 输出 | 要调试时 |
| JDK + Maven | 编译运行 Java 上位机 | 做上位机时 |
| Node.js + HBuilderX | 编译 uni-app | 做前端时 |
| 串口助手 | 看调试打印 | 要调试时 |

**`firmware/Libraries/` 和 Keil 器件包都不进仓库**，每台电脑各自准备一份，方法见
`firmware/Libraries/README.md`（里面写了从 Keil 器件包、从 ST 官方 SPL 压缩包两条路线）。

## 4. 开发流程：轮流，不并行

**同一时间只有一台是「活动开发机」，另一台保持不动。**

```
工位端：做模块 3 → 调通 → git push
笔记本：git pull → 做模块 4 → 调通 → git push
工位端：git pull → 做模块 5 …
```

- 板子 / ST-Link 接在哪台，哪台就是活动开发机，整个调试循环都在它上面完成。
- **切换只发生在「一个模块调通」这个节点**，不要在调试中途换机器。
- 人不在工位时，用远程桌面进接板子那台——它仍然是活动开发机，只是操作端在远端。

### 每次动手前

```bash
git fetch origin
git status -sb
```
落后就 `git pull`，分叉就先合并，一致才开始写。

### 每次收工前

必须 `git push`，哪怕模块没写完。没写完用 `wip:` 前缀单独提交，不要攒着——
未推送的内容另一台电脑看不到。

## 5. 唯一可以真正并行的情况：固件与上位机

`firmware/`（STM32 固件）与 `server/`、`web/`（Java 上位机与前端）是两套完全不相交的代码，
可以由两台电脑同时开发：

| 工位端（板子在这） | 用户自己的电脑 |
|---|---|
| `firmware/` 固件 | `server/` Java 上位机 |
| | `web/` 前端 |

**前提：先按 `docs/02-系统架构与通信协议.md` 把协议定死**（帧格式、字段、CRC、端口）。
协议要变，两边必须同时改协议文档，再改各自代码。

## 6. 换机器检查清单

离开一台机器前：

- [ ] `git add -A` + `git commit`（写清楚改了什么、为什么）
- [ ] `git push origin main` 成功
- [ ] 若板子要换地方，先断电再拔 ST-Link

到另一台机器后：

- [ ] `git pull origin main`
- [ ] 看一眼 `CLAUDE.md` 和 `docs/` 里有没有新东西
- [ ] 固件相关：确认 Keil 能打开工程、`Libraries/` 齐全
- [ ] 烧录相关：板子插好、设备管理器里能看到 ST-Link

## 7. 已知的坑

| 现象 | 原因与处理 |
|---|---|
| `git` 连 GitHub 报 `Connection refused` / `getsockname failed` | 本机 443 端口被代理软件（如 Steam++）占用或残留网络过滤层。退出该软件；仍不行则重启电脑 |
| 两台电脑方案不一致 | 上次就是这样：一边硬件 I2C1、一边软件 I2C。方案以 `开题报告.md` 为准，`CLAUDE.md` 已固化 |
| 江协教程代码直接抄过来不亮 | 他的引脚与本站冲突（OLED 用 PB8/PB9、软件 I2C 用 PB10/PB11，而本站 PB8 是蜂鸣器、PB11 是登记键） |
| Keil 5.21a 打开 STM32F103C8 工程闪退 / `PDSC Debug Description failed` | 5.21a 的 PDSC 解析 bug，中文路径更易触发。用 **Keil 5.24a + DFP 2.2.0**，工程固定 2.2.0 |
| `firmware/Libraries/` 突然变空 | 该目录被 `.gitignore` 忽略，`git clean -xdf` 会删掉，需要按 README 重新放 |
| 板子换到另一台就不认 | 另一台没装 ST-Link 驱动 |

## 8. 一句话总结

- **同一套代码**：轮流，一台写完 push，另一台 pull 再改。
- **固件 vs 上位机**：可以并行，协议先定死。
- **板子在哪，哪台才能调试**；其余工作两台都能做。
